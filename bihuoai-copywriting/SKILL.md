# 必火AI文案创作

这是通用文案 Skill，不包含任何特定人物的经历、口头禅、个人知识库路径或固定写作风格。只使用用户本次提供、明确选择或在当前项目中配置的资料。

## 输入规则

- 输入可以是选题、想法、已有素材、已提取的参考文稿或用户自己的个人知识库内容。
- 输入是分享链接时，先使用 `bihuoai-link-extract` 提取并保留原始文稿，再把提取结果作为参考素材交给本 Skill；不要只看标题猜内容。
- 用户已经提供并确认口播稿时，直接沿用，不强制重写。
- 参考内容只用于提炼主题、事实线索和表达结构，不把他人的经历改成用户经历。
- 资料不够时指出缺口；没有依据的数据、案例、效果和产品承诺不得补造。

## 创作流程

1. 明确这条视频要回答的一个观众问题，以及用户真正要表达的一个中心判断。
2. 从用户资料中挑选能支撑判断的事实、经历、步骤或案例。
3. 根据内容选择说明、观点或故事结构，不为套模板改变事实。
4. 写成自然、口语化、能直接朗读的完整口播稿。开头进入具体问题，正文支撑标题，结尾收住判断或给出行动。
5. 删除重复解释、空泛正确话和书面腔，检查人名、数字、产品名与专业术语。

## 交付格式

使用 Markdown 交付：

1. `## 标题建议`：3 个差异化标题。
2. `## 口播正文`：只保留说话内容，不插入字幕、画面、转场等标记。
3. `## 发布描述`：一段可直接用于发布的简短配文；没有事实依据时不添加夸张承诺。
4. `## 创作说明`：简要说明使用了哪些输入、采用了什么结构，以及仍需用户确认的事实。

时长以用户要求为准；未指定时按信息量安排，不为凑字数扩写。交付前检查开头是否具体、正文是否支撑标题、句子是否口语化，以及是否存在重复或虚构。

## 保存与修改

- 按用户指定位置保存；未指定时保存到当前项目的 `文案作品/`。
- 保存为 UTF-8 Markdown，并报告真实路径。
- 用户提出改稿意见时，优先修改当前稿件。
- 只有用户明确要求更新 Skill 时才修改本 Skill；本次文案意见与长期通用规则必须区分。

## 与视频全流程衔接

文案确认后，把标题、口播正文和发布描述交给 `bihuoai-video-pipeline`。数字人、剪辑、封面和发布阶段不得擅自改写已确认的口播正文；确需修改时先返回文案阶段让用户确认。
