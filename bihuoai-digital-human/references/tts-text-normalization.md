# TTS 朗读文本规范化

数字人使用文案和声音合成时，在提交接口前生成一份朗读版文案。目标是让 TTS 按中文口语习惯朗读，不是改写内容。

## 默认规则

| 语境 | 原文 | 朗读版 |
| --- | --- | --- |
| 年份 | `2020年` | `二零二零年` |
| 年份范围 | `2020—2023年` | `二零二零至二零二三年` |
| 数量 | `2个方案` | `两个方案` |
| 序数 | `第2个` | `第二个` |
| 小数或版本 | `2.0版本` | `二点零版本` |
| 百分比 | `20%` | `百分之二十` |
| 日期 | `2026年9月1日` | `二零二六年九月一日` |
| 时间 | `2:05` | `两点零五分` |
| 电话和编号 | `手机号13800138000` | `手机号一三八零零一三八零零零` |

年份和数量必须结合语境区分：`2020年公司成立`按年份逐位读，`共有2020个人`按数量读作“两千零二十个人”。`2个`使用“两”，`第2个`和`2.0`使用“二”。

## 边界

- 只自动处理语境明确、不会改变原意的数字。
- 无法判断是年份、数量、编号还是型号时保留原数字，继续合成，不询问用户、不阻塞任务。
- 产品型号、英文缩写后的数字和孤立数字默认保留，除非上下文足以确定读法。
- 不覆盖用户的原始文案。接口使用朗读版文案；需要留档时用 `--tts-output` 保存。
- `--no-tts-normalize` 可关闭自动规范化；音频驱动模式不处理文本。

内置脚本负责常见高置信度格式。对更复杂的自然语言，先结合全文语义生成朗读版；仍有歧义时保留原数字并继续执行。
