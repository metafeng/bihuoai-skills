# 必火AI视频封面

**文字是主角，产品与关系传达信息，人物提供信任背书。**

默认生成 **1张**。输入足够时直接制作，不要求用户填写 JSON 或选择设计方案。真实生成会消耗必火AI算力；用户明确要求“生成、制作、修改封面”即构成本次生成授权，脚本仍使用 `--confirm-generate` 防止误调用。

## 输入和素材

- 最少输入：一句标题。需要真人身份或真实场景时，还必须提供对应人物图或视频底图。
- 默认生成路径是 **人物/视频底图 + 提示词**。有可用底图时只使用这张底图即可自主设计封面，不要求用户提供成品封面参考，也不自动附加历史封面。
- 可选输入：副标题、官方Logo、吉祥物、产品截图、实测场景、关系/步骤、配色和清理项。
- 参考封面属于可选风格素材。只有用户明确提出“参考、复刻、沿用、模仿某张封面”，或明确点名某个历史案例时才加入；仅要求“生成封面”不构成使用参考封面的授权。
- 逐张识别图片用途：人物/视频底图、官方Logo、官方吉祥物、产品截图、实测场景或风格参考，不能笼统写成“参考这些图片”。
- 用户指定的人物图是身份依据。无人物图时可做纯信息型封面，但不能凭空生成某个真实人物，也不能使用其他人的照片代替。
- 最多使用 **3张参考图**，因为备用模型千问3.0 Pro当前最多接收3张。优先保留人物底图、官方Logo和最关键的产品截图。
- 使用用户明确提供的标题，可按视觉需要分成2–4行；指定换行时保留。副标题不补造。只有口播稿时可提炼短标题，但必须保留事实和原语气。
- 修改旧封面时，旧图是编辑对象；原人物图和原Logo仍可作为附加参考，不能只引用失败成品。
- 没有官方素材就不臆造Logo，可使用准确产品名纯文字。

本 Skill 属于公开的必火AI系列，**不内置任何个人照片、私人背景或个人默认素材**。当前用户可以在私有 `~/.bihuoai-skills/bihuoai-digital-human/EXTEND.md` 中配置 `cover_` 开头的素材URL；脚本只读取这些封面字段，不输出形象ID和声音ID。

## 私有封面素材

生成前可运行：

```bash
SKILL_DIR="${BIHUOAI_SKILLS_HOME:-$HOME/.agents/skills}/bihuoai-video-cover"
node "$SKILL_DIR/scripts/main.mjs" assets
```

当前私有配置支持按名称选择底图和可选历史案例，例如：

- `--asset default`：私有配置中的默认背景。
- `--asset 杭州背景`、`--asset 摄影棚背景`、`--asset 课程现场`。
- `--asset 历史封面1` 至 `--asset 历史封面9`。
- `--asset 企业AI化三层地基` 等配置中的完整案例名称。

用户未指定底图时，先查询 `assets`；存在默认背景就只使用 `--asset default`，再结合标题提示词自主设计。`assets`中存在历史案例不代表可以自动选择。只有用户明确要求参考某张封面时，才额外加入1张历史封面；它只作版式和配色参考，不能把旧文字、Logo、数字或结论带入新封面。私有素材、上传素材和URL素材合计仍不得超过3张。

## 版式选择

- `hero`：大标题 + 一个产品或结果 + 真人。
- `comparison`：两个对象围绕 VS，不无依据判定胜负。
- `workflow`：箭头连接来源、执行和输出，不能平均摆Logo代替关系。
- `tutorial`：强调用户提供的步骤数量，不自编步骤。
- `opinion`：一句判断 + 一个概念视觉 + 真人，通常白底、黑字、红色强调。

默认标题在安全区上段，关系或证据在中段，人物在中下段。按本次素材调整，但完整脸部和关键关系必须留在安全区。

## 固定设计规则

### 画布和安全区

- 默认9:16竖版，中央3:4为设计安全区，不声称平台一定按此比例裁切。
- 宽W、高H的9:16图，安全区纵向为 **12.5%H至87.5%H**。1080×1920示例：y=240至1680。
- 主标题、副标题、重点词、必要Logo、关键节点和完整人物脸都在安全区内；左右留约5%W。
- 人物躯干可以延伸到底部。顶部和底部各12.5%只放背景、留白或非核心装饰，不画裁切线。

### 文字与层级

- 层级顺序：主标题 → 1–2个强调词 → 产品/关系 → 人物 → 必要辅助说明。
- 中文粗、大、高对比，缩略图仍能读懂；使用字重、字号、颜色和底色块建立层级。
- 标题逐字准确，英文品牌大小写准确，不新增数字、口号、署名、水印或发布标签。
- 一个标题、一个核心视觉/关系、一个人物和必要素材即可，避免满屏信息。

### 人物与官方素材

- 保留人物脸型、五官比例、发型、眼镜、年龄感、服饰、姿态和真人摄影质感。
- 允许优化曝光、清晰度、自然肤色、轮廓分离、缩放和位置；无明确要求不换脸、不改手势或服装、不卡通化。
- 人物视觉权重通常25%–35%，标题应更醒目。
- Logo和吉祥物保留上传图的结构、轮廓、比例与配色，不重设计、不用相似图标冒充。
- 截图可以裁切、轻微透视、放入卡片，但不能改写关键内容或编造数据、结果与收益。

### 风格

- 默认白/浅灰底、黑粗字、少量红色强调，简洁、现代、商业科技感。
- 用户指定色或官方素材品牌色可覆盖默认红色。尽量只用一个强调色加黑白灰。
- 原背景杂乱时轻度虚化、降饱和、提亮或加浅色蒙层，保留有价值的真实场景。
- 避免电商感、游戏感、满屏HUD、电路线、机器人、强光效和五颜六色。

## 必火AI模型策略

1. 首选模型固定为 `image-2`（Image 2）。
2. 备用模型固定为 `qwen-image-3.0-pro`（千问3.0 Pro），默认2K。
3. 用户明确要求指定模型做效果对比时，可以使用 `--model image-2` 或 `--model qwen-image-3.0-pro`，只创建该模型的一次任务；未指定时仍按默认顺序执行。
4. 创建前读取 `/ai-media/model-options`；Image 2未开放或被禁用时直接使用千问3.0 Pro。
5. Image 2任务已明确失败，或成功状态却没有图片URL时，且失败不是余额、额度、权限、认证、内容审核或参数问题，自动创建 **1次** 千问3.0 Pro备用任务。
6. 轮询超时、网络状态不明或任务仍在处理中时不得自动降级，避免首个任务稍后成功造成重复扣费。
7. Image 2已经生成图片但画面质量不理想，不属于“没有生成”；先交付并说明问题。只有用户要求修改时才创建新的付费任务。

完整接口字段和状态见 [必火AI生图接口](references/api.md)。

显式使用千问3.0 Pro时默认2K：

```bash
node "$SKILL_DIR/scripts/main.mjs" generate \
  --prompt-file ./cover-prompt.txt \
  --asset default \
  --model qwen-image-3.0-pro \
  --image-size 2K \
  --dry-run
```

## 生成流程

1. 整理标题、图片角色、关系、清理项和明确要求；需要结构化时参考 [输入规格](references/cover-spec.md)。
2. 运行 `assets` 查看私有素材。默认只选择人物/视频底图；若已配置默认底图，使用 `--asset default`。用 `view_image` 查看本地图片。不要因为存在历史案例就自动使用；仅在用户明确要求参考某张封面时才按名称加入，并且不能把案例当作当前事实。最多选3张用户明确需要的素材。
3. 读取 [固定母提示词](references/master-prompt.md)，填入有效字段并删除空字段。图片编号和用途必须与 `--reference` 顺序一致。
4. 把完整提示词保存到当前工作区的临时文本文件，不把Open Key写入文件。
5. 先预演。预演会检查本地参考图、读取当前模型配置并查询两个模型的费用预估，不上传、不创建任务：

```bash
SKILL_DIR="${BIHUOAI_SKILLS_HOME:-$HOME/.agents/skills}/bihuoai-video-cover"

node "$SKILL_DIR/scripts/main.mjs" generate \
  --prompt-file ./cover-prompt.txt \
  --asset 杭州背景 \
  --ratio 9:16 \
  --dry-run
```

6. 用户已明确要求生成后，执行真实任务。`--confirm-generate`同时授权上传命令中明确列出的参考图和创建本次最多两次模型尝试；不得扫描或上传其他文件：

```bash
node "$SKILL_DIR/scripts/main.mjs" generate \
  --prompt-file ./cover-prompt.txt \
  --asset 杭州背景 \
  --asset 历史封面1 \
  --reference ./官方Logo.png \
  --ratio 9:16 \
  --confirm-generate \
  --output ./output/video-covers/主题-封面-v1.png
```

本地参考图通过同系列 `bihuoai-material-upload` 上传；也可直接使用已上传URL：

```bash
node "$SKILL_DIR/scripts/main.mjs" generate \
  --prompt-file ./cover-prompt.txt \
  --reference-url 'https://example.com/person.jpg' \
  --confirm-generate
```

7. 脚本等待最终状态、下载图片并验证文件非空且为PNG/JPEG/WebP。生成后必须用 `view_image` 查看实际成品。
8. 按质检清单核对标题、人物、Logo、关系和安全区。成功图片有缺陷时先如实说明，不自动再扣费重画；用户要求修改后，再用原素材和当前成品定向生成v2。

## 交付质检

- 标题逐字比对，副标题和英文准确，无漏字、乱码、重复或擅加文案。
- 对照原人物检查脸型、五官、发型、眼镜、衣服、手和嘴。
- 对照原Logo检查结构、颜色和比例；截图关键内容没有被改写。
- 标题最醒目，人物不挤压文字，关系和箭头一眼能懂。
- 读取实际宽高，确认接近9:16；关键内容位于纵向12.5%–87.5%的中央3:4安全区。
- 缩略图仍可读，无虚构数据、错品牌、无关装饰或水印。

不能因为提示词写了“严格保真”就宣称已经通过；必须查看成品后再判断。

## 保存和边界

- 用户指定路径优先，不覆盖旧成品；继续修改使用v2、v3。
- 未指定时脚本保存到当前工作区 `output/video-covers/`。
- 只制作封面，不自动发布、发消息、修改口播稿，也不触发数字人或剪辑任务。
- `BIHUOAI_OPEN_KEY`只从环境或 `~/.bihuoai-skills/.env` 读取，不写入Skill、提示词、状态文件或日志。
- 私有封面素材只从 `~/.bihuoai-skills/bihuoai-digital-human/EXTEND.md` 读取，不写回公共Skill或Git仓库。

## 调用示例

## 系统集成：可恢复的封面步骤

智能剪辑和一键成片使用 `create --prompt-file ... --asset 底图名称 --confirm-generate --receipt-file 私有回执路径`，立即保存封面任务编号，随后用 `detail --id` 查询并 `download --id --output` 下载。`create` 只提交一个模型，不等待、不自动切换。仅原任务明确失败且符合既有降级规则时，宿主才可用新回执文件提交千问备用模型。提交未知、超时或服务重启时，先读取回执核对原任务，不能重新创建。系统默认使用后台当前底图，可在剪辑页改选；封面主副标题使用用户确认后的文字。
