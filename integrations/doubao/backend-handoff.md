## 1. 工具实际总数

2026-11-17 旧评测记录为 60 个工具；这不是当前实时计数。正式提包前，授权生产账号调用 tools/list，跟随 nextCursor 直到结束，总数须不超过 30。

backend-contract.json 提供当前创作流程需要的 20 个已知工具名称，以及绑定账号、发布回执等补充能力。先核对生产工具定义，再形成完整允许清单。不能通过删除能力造成流程不可用，也不能编造工具名称。

在生产服务的客户端或授权作用域中实现白名单，使 tools/list 与 tools/call 使用同一作用域。不能仅修改技能说明或增加平台未支持的 mcp.json 过滤字段。需要保留其他客户端功能时按注册客户端或受控授权范围区分，不能仅信任可伪造的请求头。本包继续使用用户指定的生产 URL。

## 2. OAuth DCR 与豆包首次授权

公开安装说明目前列出的回调主要为本机及 WorkBuddy；不据此判断豆包一定失败，但必须实测豆包真实回调。

检查未授权 MCP 返回 401 与 Bearer resource_metadata 挑战；公开 PRM、ASM 均为 HTTPS JSON 且不重定向；resource 与 MCP URL、issuer 与选中授权服务器逐字符一致。DCR 支持公共客户端，authorization_code + PKCE S256，token_endpoint_auth_methods_supported 是包含 none 的无重复字符串数组。

按豆包实际文档及真实注册请求支持所需回调，不要添加猜测回调、放开任意 HTTPS 域名或关闭回调精确匹配。授权码须与 client_id、redirect_uri、PKCE 绑定且一次性使用。所有凭据由运行环境托管，不能进入公开包。

probe_oauth.py 只验证公开挑战和元数据，不执行 DCR 注册、授权码交换或真实用户授权；元数据通过仍须豆包端首次安装验收。

## 3. 输入输出审核与幂等

创作、数字人、封面、剪辑、发布各接口在服务端做输入审核，生成结果做输出审核；审核未通过时不返回可发布的交付结果。对客户端返回可解释的拒绝、待审或通过状态。插件内的编排规则不能替代服务端审核。

对数字人形象、声音与原素材执行对应授权校验。实际费用、额度及是否已扣费须可查询。写入与扣费接口需要幂等和任务查询，使客户端超时后复用原任务而不重复扣费。

## 4. 素材上传链路

prepare_file_upload 是准备上传，不等于字节已上传。核实豆包当前附件能力与服务端支持的真实链路；没有可用链路时，按包内说明引导用户到平台素材页上传，再查询已完成的素材。不可声称已实现自动上传。

## 5. 豆包客户端验收

使用全新安装、未预授权的测试账号，有真实可用额度。验证首次 OAuth、账号资源查询、数字人成片、封面、剪辑、素材保存、发布草稿及最终回执。付费生成与外部发布分别取得相应确认。对中断恢复、过期授权、审核拒绝、余额不足进行验收，保留脱敏任务 ID、状态与实际结果。

完成上述项目后，才能把候选包认定为完成提审自查。上传并保存草稿不等于完成业务验收或提交审核，实际后台状态见本轮评测报告。
