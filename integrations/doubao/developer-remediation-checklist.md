## 2. 已确认必须修改：DCR 回调与名称准入

在现有动态注册接口 `/oauth/register` 增加豆包规则，保留现有 WorkBuddy 和本机规则：

| 字段 | 要求 |
| --- | --- |
| client_name | 如存在名称白名单，允许精确名称 `Doubao Connector` |
| 协议 | `https` |
| Host | 精确为 `api.doubao-dev.com` |
| 路径前缀 | `/api/oauth/v1/callback/personal/cb_ah_`，后缀由平台动态生成 |
| URL 边界 | 默认 HTTPS 端口；拒绝用户信息、片段、非标准端口、相似域和伪装子域 |
| 登记内容 | 逐条检查 DCR 请求中的 redirect_uris，保存该客户端实际提交的完整 URI |

`https://api.doubao-dev.com/api/oauth/v1/callback/personal/cb_ah_*` 是准入模式，星号不是实际登记字符。不要猜固定地址，也不要将我们使用过的合成诊断地址当作生产回调。

使用 URL 解析器分别验证协议、Host、完整路径前缀，不能用“包含 doubao”判断。前缀规则仅用于注册准入；授权请求和换 Token 时仍精确匹配该客户端登记的完整 URI。client_name 可由请求方填写，不能当作可信身份或跳过其他校验的依据。

如框架只支持提前逐条精确登记，必须本轮明确此限制，由生态团队取得真实回调后逐条登记；不能由伙伴猜测。

验收：两个不同动态后缀的诊断 URI 可通过注册准入；HTTP、错误 Host、`api.doubao-dev.com.evil.example`、用户信息伪装、错误路径及非标准端口均被拒绝。诊断不是完整授权验收，最终使用豆包真实 DCR 请求走完整流程。

## 3. OAuth / MCP 集中核验，已正确的保留

| 项目 | 通过标准 |
| --- | --- |
| MCP 未授权响应 | HTTP 401，Bearer challenge 指向正确 Protected Resource Metadata，不返回登录页 HTML 或假成功 |
| PRM / ASM | 公网 HTTPS 合法 JSON；resource 与当前 MCP URL 精确一致，issuer 与授权服务一致，各端点真实可用 |
| DCR Public Client | 支持 `token_endpoint_auth_method: none`；动态创建并持久保存 client_id，按指南不设到期时间，服务重启不丢失注册信息 |
| 用户授权 | Authorization Code + PKCE S256；校验 Client、登记的完整回调、Scope、Resource，原样返回 state，保留用户确认 |
| 授权码 | 短时一次性，绑定 Client、Redirect URI、Scope、Resource、PKCE；错误绑定、错误 verifier 和重用必须失败 |
| Token Endpoint | POST application/x-www-form-urlencoded；Public Client 不要求 client_secret；成功 HTTP 200 标准 OAuth JSON，不包装业务 code/message/data |
| MCP Token | 校验有效期、受众、Scope、用户权限，不能跨账号读取资源 |
| Refresh Token | 如元数据声明支持，验证刷新、轮换、失效及并发策略，不能只声明不可用 |
| API Key 额度与重试 | 核对此前额度耗尽问题；有效连接可复用，失败重试不持续遗留占位；不绕过正常额度限制 |
| 网络与网关 | 公网 HTTPS Streamable HTTP、有效证书，网关/WAF/限流不误拦豆包正常请求；无拦截证据不额外扩大访问权限 |
| MCP 协议 | 按协商版本处理，旧版 initialize/Session 与新版逐请求规则不混用；不为本次问题盲目升级协议 |
| 工具 Schema | inputSchema 顶层 object；按指南替换 type 数组、内联 $ref/$defs/definitions，递归结构改造或专项确认；outputSchema 与 structuredContent 一致 |

公开元数据、本机授权已有部分通过证据；本轮仍须完成真实豆包云端 DCR → 用户授权 → 换 Token → tools/list → 至少一个无副作用工具调用。错误响应应可定位，不能以整页前端 HTML 代替接口结果。
