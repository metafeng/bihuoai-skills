# 文案创作

使用用户本次提供或明确选择的选题、产品资料、经历和参考素材。参考链接需先按链接提取流程获取正文，不凭标题猜测内容。

1. 明确目标观众、要解决的一个问题和核心观点。素材不足时指出缺口，不补造数据、案例、效果、资质或经历。
2. 只借鉴参考内容的主题、事实线索和表达结构，不把他人的经历写成用户的经历。
   用户描述想尝试、如何做或提供目标场景时，不写成“我们现在已经这么做”的既成经历。未提供录音、讲义、客户案例或实施结果时，不自行补为真实素材；可以明确写为建议步骤或待确认项。
3. 写成自然、完整、可朗读的口播稿。开头进入问题，正文支撑标题，结尾收住判断或给出行动。
4. 删除重复、空泛口号和书面腔；核对人名、数字、产品名称和专业术语。
5. 按内容安全说明审核输入与稿件，用 Markdown 交付“标题建议”（3 个差异化标题）、“口播正文”（只保留说话内容，不插入字幕、画面、转场标记）、“发布描述”（一段简短配文）、“创作说明”（输入来源、结构及待确认事实）。时长按用户要求，不凑字数。
6. 让用户确认最终稿。用户已提供并确认文稿时直接沿用，不强制改写。

写文案不调用数字人、生图、剪辑或发布创建工具。需要保存平台草稿时单独说明写入动作并确认。只有环境确实支持保存文件时，才按用户指定位置保存并报告真实位置。

用户已明确要求保存但未指定位置时，在当前任务具备文件保存能力的前提下保存到“文案作品/”，UTF-8 Markdown；不支持文件保存时交付可复制正文并说明限制。改稿优先修改本次已有稿件，不把一次改稿意见写成永久规则。确认后将标题、口播正文和发布描述交给同一入口内的后续流程；后续阶段不得静默改写。
